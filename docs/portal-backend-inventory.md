# 校宝学生端：页面与 Rust 接口对照

复核日期：2026-11-18（上海时间）。范围：当前学生角色可见的校宝主站，不包括老师端、家长端、iPad 原型自己的页面或另一个学习系统。

## 数量与证据

- **7 个顶栏业务栏目**：我的测评、我的任务、我的考试、我的考勤、我的资料库、我的日程、动态成绩。栏目不是页面数，也不是按钮数。
- **14 个已实地打开的业务页面或独立路由内页**：任务 3、考试 3、测评 1、考勤 3、资料库 2、日程 1、动态成绩 1。按浏览器顶层地址去重是 **11 个**；考勤和资料库按各自独立地址的内页展开，并且不重复计算外壳后是 14 个。
- 同路径的筛选标签、抽屉、弹窗和分页不另计。登录、找回密码、语言、账号及「切换到学习系统」是辅助入口，不计入业务页。
- 首轮因原站跳回登录，只定位了 6 个路径，部分来自附件记录。用户重新登录后，以下 14 个内容页均用实际导航验证，取代首轮暂计。清单不记录原站账号、实际成绩、课程名称、附件内容或凭据。

## 已定位页面

Rust 路径的共同前缀为 `/api/v1`。原站路径里的 `#!` 是浏览器前端路由，不是 Rust API 路径。下表考勤、资料库和测评的第二个路径是宿主页包裹的内嵌内容地址，不是额外计数。

| 页面 | 实测原站路径 | 界面功能 | 已实现的本地 Rust 数据接口 |
| --- | --- | --- | --- |
| 任务列表 | `/Home#!/task/list` | 学期、课程、任务类型、任务模式、日期筛选；标题搜索、重置、分页；查看截止时间、老师、批改状态和数字或字母成绩。 | `GET /work?kind=task` 支持学期、课程、类型、模式、日期和批改结果；老师名称可由 `GET /courses` 对照。 |
| 任务详情 | `/Home#!/task/list/detail` | 已批改记录可读。显示学生姓名、任务类型、时间、内容、附件区域及任务成绩；没下载附件。 | `GET /work/{id}` 提供基础详情、批改状态和带类型的成绩，也可提供发布时间、回答和点评；附件只有显示用元数据。 |
| 任务统计 | `/Home#!/task/stat` | 按学期、课程、类型、起止日期筛选；历次任务得分率图表、表格和排序。表列：标题、任务类型、得分、任务总分、得分率、截止时间。 | `GET /work-statistics?kind=task` 返回分页表格和可绘图的数据。没有有效的数字得分率时返回 `null`。 |
| 考试列表 | `/Home#!/exam/list` | 选学期、类型和日期，搜索、重置、分页；列表展示考试时间、成绩。当前学期默认范围为空，往期有记录。 | `GET /work?kind=exam` 提供考试时间、类型、成绩和筛选；本地演示有一场往期已出分考试。 |
| 考试详情 | `/Home#!/exam/list/detail` | 从已公布成绩的历史考试进入，可查看学年学期、考试时间、类型和分科成绩。 | `GET /work/{id}` 提供考试时间区间、总成绩（有则显示）和多科结果。 |
| 考试统计 | `/Home#!/examstat` | 学期、类型、起止日期筛选；历次考试得分率图表和表格。表列：课程、考试名称、类型、课程得分、课程满分、得分率、考试时间。 | `GET /work-statistics?kind=exam` 返回每次考试的分科行，按课程得分 ÷ 课程满分计算。 |
| 我的测评 | `/Home#!/assessment` → `/newstu/assessment/list` | 全部／未完成／已完成是同页筛选；当前账号下观察到空列表，没验证测评详情或填写流程。 | `GET /work?kind=evaluation` 提供只读演示列表和 `status` 筛选，无填写接口。 |
| 上课考勤 | `/Home#!/attendance` → `/newstu/attendance/class` | 日期范围和快捷区间、四类考勤次数、出勤率、逐科表；课程详情是可按出勤状态筛选并分页的抽屉。 | `GET /attendance?category=classroom` 沿用原课堂汇总、逐科和原始记录格式，可按 `course_id` 取课内详情所需的数据。 |
| 日常考勤 | `/Home#!/attendance` → `/newstu/attendance/daily` | 独立内页，同类日期筛选与统计；表列考勤日期、班级、出勤状态、请假状态。 | `GET /attendance?category=daily` 返回独立的日常记录、日期、班级和请假状态。 |
| 活动考勤 | `/Home#!/attendance` → `/newstu/attendance/activity` | 独立内页，同类日期筛选与统计；表列活动时间、活动名称、出勤状态。 | `GET /attendance?category=activity` 返回独立的活动记录、开始时间、名称及统计。 |
| 分享给我的 | `/Home#!/cloudDisk` → `/newstu/disk/share-with-me/all` | 日期、分享老师、类别、搜索、刷新；网格／列表切换；列表列有文件、大小、分享老师、分享时间、操作。未验证实际文件操作。 | `GET /resources?scope=shared` 返回分享老师、时间和大小，并可筛选分享者、类别和日期。 |
| 我的资料库 | `/Home#!/cloudDisk` → `/newstu/disk/cloud-disk/all` | 有自己的地址和搜索入口；访问时列表为空，未确认实际上传、下载和文件管理。 | `GET /resources?scope=personal`、`GET /resources/{id}` 提供演示文本与只读检索。 |
| 我的日程 | `/Home#!/schedule` | 周／月视图同地址，前后翻页；校历、活动、课程开关；全天行、时段和地点。 | `GET /calendar`、`GET /schedule` 返回课程及分类型事件；校历与活动在 `events.kind` 中分开，前端负责周／月展示。 |
| 动态成绩 | `/Home#!/realtime/list` | 学期、班级类型、课程名筛选；显示学期 GPA 和课程成绩；课程卡在同页打开含权重、成绩和可展开记录的详情弹层。 | `GET /grades` 提供两个演示学期、按班级类型/课名筛选、公布时间、字母等级和评估权重。不推算官方 GPA。 |

## 不计入页面、暂不实现的操作

- Teams 是挂在任务页的浏览器扩展浮层（可见面板加载了扩展资源），不改校宝路由，不计入原站业务页或本次后端范围。
- 课程考勤详情抽屉、动态成绩详情弹层、周/月日程、测评状态筛选和资料类型筛选不是新页面。
- 尚未核实测评详情、任务提交、考试作答、附件下载和文件管理。未执行提交、开始考试、下载或修改记录等操作。

## 后端实施（已完成）

保留现有拆分：iPad/网页负责渲染、交互和周/月视图；Rust/Axum 负责验证会话、按账号读取本地演示数据、筛选和计算。数据流：**前端 → `/api/v1` → 验证演示会话 → 读取该账号的合成数据 → JSON → 前端**。不导入校宝 HTML、真实数据或登录凭据。

新增 `GET /api/v1/work-statistics` 一条只读路由。任务与考试统计共用 `src/work/` 的筛选和分页；三类考勤共用 `/attendance`，但有各自记录和覆盖区间。测评、资料库、日程和成绩继续复用已有路由。未改 iPad/网页界面、数据库、环境变量、应用依赖或部署；没有接入学校、Teams 或真实文件。[接口契约](../xiaobao-backend/API.md)和[请求示例](../xiaobao-backend/requests.http)是联调入口。

```text
xiaobao-backend/
  src/
    lib.rs             # 注册新的只读路由
    api.rs             # 通用校验、成绩、日程和资料读取
    domain.rs          # 兼容旧响应的可选数据字段
    work/              # 列表、详情、共用筛选和统计
    attendance/        # 三类考勤查询和覆盖处理
    provider/demo.rs   # 合成演示数据
  tests/
    api/portal_pages.rs # 筛选、成绩边界、账号隔离
    device_cache.rs    # 缓存与离线版本回归
  API.md               # 公共契约
  README.md            # 覆盖范围和变更记录
```

兼容性边界：历史工作和成绩、日常及活动考勤通过在线 GET 读取；原有离线模块键和课堂考勤载荷没有改变。前端要使用新增字段或统计接口，仍需要在客户端接入，Rust 不渲染这 14 个界面。

### 本地验证（2026-11-18）

- Rust：格式检查、32 项测试、Clippy（警告视为错误）和 Release 构建均通过。
- 实际启动 Release 二进制，仅监听本机临时端口，用演示账号逐一请求，14 个页面数据用例均返回成功。
- 使用附件原版 Swift Core 解码器验证了 12 份在线响应和 9 个离线模块。该验证不等于已修改或运行 iPad 界面。

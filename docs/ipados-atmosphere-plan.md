# iPadOS 天空背景：方案与实现记录

状态：**程序化渲染预览已实现。** 参考图不进入 App。贴图原型只作历史对照，资源保留在 `Trash/2026-11-19/sky-photo-prototype/`，不再参加原生构建。

## 当前路线：程序化体积天空

**不再沿用的路线：** 即使换成夜景原图、增加前后几张云图的视差，形状仍然是预先画好的。把新图铺在夜间、加暗罩或增加平移速度，都不能解决云本身不变化的问题。已生成的原图保留作视觉对照，不导入下一版运行资源。

**实现：** 用 [Metal](https://developer.apple.com/documentation/metal/) 按帧渲染程序生成的三维云密度。用随时间变化的细节噪声和风场让云在移动时卷动、变形、消散；沿视线累积云密度，按太阳或月光方向计算亮边、阴影与遮挡。月亮与星空在云层后面，固定灯光时也能被变化的云遮挡。两份三维缓存由代码在设备上生成，不包含天空照片或预渲染帧。

```text
Xiaobao-iPadOS/
  Sources/Core/Atmosphere/             # 复用现有时刻、日期和 35 种天气参数
  Sources/Native/Atmosphere/
    SkyBackdrop.swift                  # 替换既有背景入口；页面调用方不变
    SkySurface.swift                  # SwiftUI/MetalKit 桥接和帧调度
    VolumetricSky.swift               # 生成并复用 GPU 缓存，编码渲染
    VolumetricSkyState.swift          # 日历光照与独立的云运动参数
    Shaders/VolumetricSky.metal         # 天空、云密度、光照和遮挡
  scripts/generate_project.py          # 把 Metal 源文件加入现有构建
```

输入路径：本地日期、时刻和已选天气 → 云量、云高、风、散射和能见度的渲染参数 → 原生背景。渲染器不发 HTTP 请求；后续接入的[城市天气模块](../Xiaobao-iPadOS/Sources/Core/CityWeather/README.md)在其上游提供东莞当前条件或有标记的缓存，手动预览仍可离线使用。业务页不需要新增天气控件，Rust、数据库、环境变量与部署不变。现有粒子、水汽和可访问性设置保留；有需要时采用更简化的代码渲染，不退回背景图平移。

### 实现验收（2026-11-19）

- iPad Air 11 英寸（M4）iPadOS 26.4 **模拟器**：实跑白天多云与月夜。锁住月夜场景时刻，关闭动效时所测可视背景区域的两帧像素一致；开启后同区域变化明显。
- 同一程序的 Metal 离屏探针：固定灯光时，相同运行时刻的两帧字节一致，推进运动会改变云形，月盘边缘变化明显高于保留的空天空区域。初次测试中的横向采样纹与过度颗粒已通过双点区间和有界抖动减轻；云边与照片仍有观感差异。
- 35 个现有天气方案都向新渲染器提供参数，离屏渲染各有不同结果；雨、雪、冰雹等原来的 SwiftUI 程序粒子照常叠加。不是每一个天气在 iPad 上逐一进行了视觉验收。
- 60 项 Swift 核心和演示集成测试通过；发布配置的模拟器构建通过。画质接受程度、真机帧率、发热与耗电仍需真机验证。截图及录像仅用于展示，不参与 App 绘制。

## 节日与二十四节气：实时三维美术

**首次接入（2026-11-21）；造型由下方现行路线替代。** [当前场景和二十四节气交互清单](../Xiaobao-iPadOS/Sources/Native/Atmosphere/Seasonal/README.md)。 范围是澜图 App 的整套节日与节气背景，从主角到远处的一点火星；不是把课表界面改成三维。在原体积天空上增加三维几何；旧 Canvas 节日灯笼、灯串已替换。

- **形体和光。** 在同一套相机与空间坐标中，用 Metal 实时画有形体的几何、体积介质或三维粒子。灯笼的灯骨在透光的纸面之后；礼盒翻转时能看到不同的面；烟花在不同深度绽开，发光影响邻近云层。不能用朝向镜头的贴片、Canvas 剪影、分层平移或预渲染影片冒充立体场景。
- **时令构图。** 除夕守岁窗灯、春节烟花、元宵莞式千角灯与远处天灯、清明柳影、端午龙舟、七夕鹊桥、中秋月兔、重阳山径、万圣夜南瓜灯、感恩节暖窗长桌、圣诞雪橇、元旦晨光各有主景。二十四节气的小景也按同一三维标准制作，不用更换天气来表现时令。清明、冬至各自只画一幕。
- **角色行为。** 保留现有天空的月亮与云层关系。中秋玉兔从右往左，点中可提前落入低云；圣诞雪橇从左往右，点中只有机会掉下翻滚的礼盒，不会改变飞行轨迹。天空本身仍不接管输入；只在未被前景控件占用的区域识别角色和节气景物的触碰，滑动仍交给原页面。
- **验收。** 在离屏测试里固定同一时刻，从两个机位观察，核对近远物体的相对位移、侧面轮廓和云层遮挡；不为此在 App 增加镜头操作。减少动态效果时取同一三维场景的静帧，不另换一张图。固定时刻双机位、冻结复现、可见云遮挡、37 景输出和 24 种响应由 [Metal 探针](../Xiaobao-iPadOS/Tests/AtmospherePreview/README.md)检查；真机帧率与耗电未测。

**上一版验证（2026-11-21；片元数仅对应当时的模型）。** 在 768 × 576 的实际 GPU 输出上，37 景的逐帧指纹均不同，24 个节气的固定时刻触碰对照均有变化。分别点水面左右两处时，变化跟随各自落点；同一只玉兔在晴夜有 3,845 个可点片元，被厚云完全遮住时为零。iPadOS 26.4 模拟器的 5 项触控测试通过，覆盖空处与甲虫、拨叶与前景按钮、点水与滚动、飞行角色和手动选景。另验证了切换六个侧栏页面不会重建天空。以上是离屏与模拟器结果，不代替真机测量。

### 现行路线：时令套色版画（2026-11-22）
全部 37 景重绘。天空沿用原有体积天气；景物自成一套分色和留白，不要求拟真。飞行角色用薄浮雕和负形表现，近物保留能识别物种、材质和触碰的局部细节。[全部节日、节气和动作](../Xiaobao-iPadOS/Sources/Native/Atmosphere/Seasonal/README.md)是现行清单。

- 元旦石拱的孔是真空，沿河台基与不透明的墙遮住云；飞在空中的主角仍可能被厚云遮住。端午的划桨与船体倒影同步，七夕把桥心留给相会的人，重阳的石路、山亭与人同用一条山脊标高。
- 春节和元宵每次进入有新的随机种子；冻结不会闪变，继续播放会有新的事件。元宵既有升空的天灯，也有较远、与其错时的随机烟花。玉兔与月盘共用投影；平安夜使用较小的银色剪影，圣诞的礼物只在命中成功时从袋口落下。万圣夜通过右檐下雕灯镂空的眼口表现绿火，三次落定后才旋转。
- 不再尝试以增加毛发数量解决远景角色比例、用同一只鸟等距排队冒充一座桥，或以全屏滤色统一画风。真实水体、倒影、羽缘仍服务于具体画面，不是所有场景都要模拟摄影视觉。

**初版套色实测。** 37 景的 Metal 实际输出和 24 个节气的命中后变化均通过。横屏 768 × 576 测得兔宽 49、月宽 60 像素；竖屏 576 × 768 为 65 对 81。元旦额外比较了厚云下不透明墙内部的原始光色与最终画面，元宵另测近挂灯、远天灯和更远的独立火花轨迹。万圣夜按时间检查三次跳跃与后续整圈旋转，并在 iPadOS 26.4 模拟器进行真实点按。7 项模拟器触控测试、Release 构建通过；未测实体 iPad 的持续帧率与功耗。

**后续四景校样。** 在同一光照和输出尺寸下分开检查船桨与镜面、人物与桥面、花被与莲心、丝线与露珠，不重画已经定下的月兔或雪橇。端午与大暑复用场景的局部水线；七夕采用留空的羽桥；寒露的波从实际触点传播。中间试过却不再沿用的造型及原因见[时令修改记录](../Xiaobao-iPadOS/Sources/Native/Atmosphere/Seasonal/README.md)。`impression-reel` 可重放这四幕，`seasonal` 中的结构断言另行验证运动。本轮横、竖构图各回归 37 景及 24 个节气触碰；12 支桨分别经历入水和回桨。8 项 iPad 模拟器触控测试（含细网和莲瓣）通过，Release 已在专用天气 QA 模拟器验证，未在实体 iPad 上测试。

### 历史中间版：写实材质与近摄（2026-11-22；不是现行美术目标）

上一版已满足「在三维空间中移动」，但同机位近照暴露出四肢拼接、花瓣同形、岸或房屋悬空，以及各材质共用塑料般反光的问题。**不沿用的路线**：增加色彩饱和度、加屏幕噪声或只拉高分辨率。新路线先改形体与支承，再改光如何透过／反射，最后对比真实帧；不是通过铺一张照片遮盖低模。

这次中间版的 37 景走[原生时令模块](../Xiaobao-iPadOS/Sources/Native/Atmosphere/Seasonal/README.md)的实体投影与材质管线。先后用两机位检查，实际修正过过直的芦叶、同轴梅花、近岸截面露底，以及屏幕空间追踪导致龙舟倒影破碎的问题。水面改用独立镜像相机；透光表面读取同一帧后方不透明景物；雾化边缘不是新的命中区。只改本地画面，无学校业务、网络、数据库或部署更改。可重跑的质量与交互检查和局限见[外观探针](../Xiaobao-iPadOS/Tests/AtmospherePreview/README.md)。当时的目标是与云同等可信，不能把自动测试通过当作照片级美术验收。

**小寒单景校准（2026-11-22）。** 以栖鸟照片只作外部观测，对照同视点、同尺寸的羽缘、胸颊、眼睑和握枝。原来的展翅模板、整块腹羽以及广角贴近主体这三种做法为何失效，记录在[时令模块的修改历史](../Xiaobao-iPadOS/Sources/Native/Atmosphere/Seasonal/README.md)。这次校准使用按需建立的独立雀体和两侧羽序；参考图不在资源包中。可用 `sparrow` 探针取得原像素裁幅、另一侧和同一时刻的蓬羽对照；这些证据只适用于小寒，不能替其余场景验收。

**本轮复测。** 900 × 675 的标准机位和近机位覆盖全部 37 景；11 景另取现有天气／时刻看受光变化。768 × 576 固定时刻的 24 种反馈、左右两处水波、玉兔提前落下、礼物不改变雪橇和厚云遮挡均通过。独立灯光台只换水边物体的色料，有 3,587 个真正标为水的片元随倒影改变；只换露珠后方的色料，露珠内的像素随之改变。iPadOS 26.4 模拟器的 5 项触控回归和 Release 构建通过；实体 iPad 的热与耗电不在这组测量内。

## 第一版记录：贴图与程序粒子

## 视觉目标

从参考图取真实云层的体积、云边细节和受光，不复制网页、文字或布局。晴、多云、阴分别使用不同的 4:3 本地图片；原生视图按比例裁切。可变光线、降水和遮蔽层独立于图片和页面。

## 时间与日期

- 默认沿用上海时区。晨光、白昼、黄昏、夜间连续改变亮度、色温和云层受光；不硬切四张形状不同的壁纸。
- 日期通过本地季节规则改变白昼长短、日落时刻和天光色温。节日识别沿用现有规则；现有环境面板可预览时刻，背景不改动课表时间。
- 环境面板可选择 35 种预览，包括各级雨雪、强度区间、雷暴、冰雹、台风、雾、霾和沙尘。旧「雨」「雪」偏好继续识别为中雨和中雪。不请求定位或天气联网。

### 已修改的文件

导入已验证的 SwiftUI 源工程作为独立原生目录，不覆盖预览包、不移动 Rust 工程。复用环境面板和系统天气选择器，不新增业务页面、入口按钮或外部接口。

```text
Xiaobao-iPadOS/
  Sources/Core/Atmosphere/              # 天气条件、强度曲线和按日期变化的光线
  Sources/Native/AppModel.swift           # 把现有时钟、日期和环境设置传给背景
  Sources/Native/Atmosphere/            # 云图、对比度、能见度和分批粒子绘制
  Sources/Native/EnvironmentView.swift  # 复用面板，分组选择天气
  Resources/Assets.xcassets/             # 三张天空资源
  Tests/Core/                          # 天气目录与偏好、时段连续性、季节差异
  README.md                              # 更新原生背景说明和变更记录
```

数据流：设备时间和日期、现有环境设置 → 背景光线与云层状态 → SwiftUI 背景。卡片、侧栏、现有控制和 Rust 不改；无需改数据库、API、环境变量或部署。色彩规则集中管理，不在业务视图单独写一套配色。

### 验证边界

贴图原型已通过模拟器编译与代表性实际画面检查；天气与日期核心共 58 项测试通过（含独立回环演示服务的集成测试）。原生界面验收发现系统选择器将分组标题也显示为可选行，已改用真正分组的列表；随后的界面测试未能启动模拟器测试运行器，因此新版选择流程和横屏不能标为通过。新夜景的移动贴图方案未写入项目、未出包。iPhone 适配、真机签名以及真机性能还未验证。

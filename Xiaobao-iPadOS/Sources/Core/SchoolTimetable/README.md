# School timetable · 本机学年课表

A device-local document for the currently enrolled portal student, independent of login bindings,
personal plans, and the online academic store. No backend, new endpoint or background job.

- **Inputs:** verified owner, foreground read of actual Sunday–Saturday records, and the published Main Campus HS calendar for the academic year. Never use sample courses or infer holidays from weekdays.
- **Output:** dated lessons/events and verified Day 1–6 lineups for Today and Planner. Read the current week first, then at most five nearby teaching weeks; stop when all six are corroborated unless dated TSSA registrations need the remaining samples for weekly time evidence. Only repeat course/time assignments supported across distinct teaching dates as described below. Differing rooms are not repeated. Unknown dates are not empty classes. Events are date-only.
- **Rotation coverage:** The same Day must be observed on at least two distinct teaching dates. On this campus each of those dates needs a daytime lesson or explicit vacancies covering the whole instructional day. A partial vacancy can contradict a proposed lineup but cannot confirm one. Matching late-only rows are not enough; all actual daytime observations must agree, with no majority vote. All occurrences still participate in comparing late intervals. A genuine daytime conflict or closure is never filled by voting. Restoration rebuilds derived Day templates from the saved dates, without modifying the protected document, issuing a school read, or changing registration.
- **Partial future edge:** A partially delivered week can stop publishing daytime lessons before its late registrations. Only for sampled dates *after both the import date and the last dated daytime evidence*, under a published teaching Day with a corroborated regular lineup, `Day.usesDaytimeRotation` marks a display-only daytime projection. Dated late rows are retained verbatim; no missing late class is added here. Explicit vacancies, published notices, dated events and gaps inside the observed period take precedence. The edge is recalculated when more weeks arrive; it is never persisted or used to create additional course alerts.
- **Campus bells:** for Main Campus HS 2026–27 only, normal dated/corroborated rosters share the daytime bells with Today and Planner. A matching pair of halves of the same opening class becomes one 08:00–09:20 enrollment before IDs are discarded. The portal labels 08:25–09:05 and 09:15–09:55 as the two opening halves, and 12:35–13:15 as the pre-lunch bell. Exact standard afternoon times stay unchanged. Different enrollment keys remain separate; off-grid outings and closures retain their times. Unversioned archives are corrected at read time, before both display and alert projection. Without keys, only the unique known opening pair with matching name and room can become one class; no refresh is required.
- **Explicit blanks:** optional `datedVacancies` records only recognized bell intervals, never a credential or student identifier. A partially observed, blank-only date confirms those slots alone, not an entire free day or a recurring lineup. An empty/malformed response is not evidence of a vacancy. Published teaching dates always show full assembly and lunch, even without a confirmed roster. An unknown roster is still marked unknown and creates no vacancies or course alerts. Optional blocks, dinner and boarding routines belong only to Planner.
- **Class reminders:** `lessonReminders(now:lead:calendar:)` projects only distinct confirmed starts over seven Shanghai dates. Output is the fire time and lead, never a lesson title, room or account ID. The opt-in is bound to the saved document’s random registration; another student does not inherit it.
- **Next school day:** `nextSchoolDay(after:calendar:)` starts strictly after the given Shanghai date. It skips confirmed closures, accepts published weekend teaching or actual dated lessons, and stops at a gap or the end of coverage. A printed Day on a closure is never a rotation. A published teaching date is still returned if its first lesson is unknown; simultaneous starts are retained, not arbitrarily ranked. No read or file write occurs.
- **Files:** `SchoolTimetable.swift` selects sample weeks and projects one common day; `SchoolBellAlignment.swift` matches source intervals before rotation comparison and during legacy projection; `SchoolRotationEvidence.swift` compares dated occurrences of a Day; `SchoolTimetableStore.swift` rebuilds the derived index when restoring a matching publication and stages a replacement, accounts for cancellation and holds one protected non-backed-up document. Only publish after the file write succeeds. A poorer or failed replacement leaves the old timetable available. If the first import loses the network after already verifying dates, only those confirmed dates are saved as partial, with no automatic retry. If the device is offline, Settings can recheck an existing session without submitting a password. A saved year can only be projected using the matching year and calendar revision.
- **Boundaries:** an offline timetable is visible to whoever can unlock this personal iPad. It never authorizes any network request or access to grades or personal plans. If the student separately enabled foreground login restoration, it can restore the live session on launch without blocking Today; the timetable does not trigger that credential use. Opening the manual portal suspends offline display across process death until the same account is verified. Sign-out, local school data removal or account change revokes the archive registration before file cleanup.
- **Consumers:** `Native/SchoolPortalSync/SchoolTimetableAccess.swift`, Today, Planner and the existing Settings action. See the repository reusable module index for the call sites.
- **Tests:** from the iPad directory run `swift test --filter SchoolTimetable`. The simulator uses a loopback fixture, never a real student.

## Change History

### 2026-11-22 — late-only-rotation / reminder-revalidation
Model: OpenAI Codex. Exact agreement previously accepted a nonempty lineup before checking daytime coverage. Apply the two-date daytime prerequisite to both rotation comparison paths so incomplete imports and old archives no longer promote late-only records to other dates. Keep the original dated rows and their eligible reminders. Interfaces: unchanged `SchoolTimetable.day` and `lessonReminders` signatures, archive format, and reminder opt-in. On the next foreground reconciliation the existing queue drops pending requests no longer supported by the timetable. Regression: `SchoolTimetableRotationCoverageTests` exercises partial and fully vacant teaching slots, dated reminders, and offline restoration of an older archive without rewriting it or contacting the portal.

Verification: reproduced both the unsynced class and its reminder candidate before the fix. After it, 290 core tests (including the loopback Rust integration), 35 portal bridge tests and the unsigned iPadOS Release build passed. No physical-device notification was tested.

### 2026-11-22 — inactive-overlay / optional-lesson-fields
Model: OpenAI Codex. The display adapter keeps the same saved timetable during a temporary system overlay; active I/O remains gated. Successful imports can carry known optional year/class/teacher/note labels on a period, without making those fields evidence for a lesson or changing its bell. Distinct labels do not get assigned to inferred occurrences; notes remain dated. The existing archive decodes and displays without them.

### 2026-11-22 — weekday-evening / return-day · diagnosed, not fixed in build 7
Model: OpenAI Codex. The annual daytime check does not validate an evening enrollment's dates. Late periods are still compared *within each numbered teaching Day*: a weekday-based session can appear to belong to just one Day and later land on the wrong weekday. Planner's separate overnight reference rule also does not handle a non-Sunday holiday return; a confirmed weekday evening interval is not evidence for an afternoon return interval. No runtime or interface change in this diagnosis. For regression, withhold entire source weeks, then compare actual per-account occurrences (including missing and extra periods), not the presence of any class that day. Distinguish weekday, teaching-Day, dated-only and boarding-return cases; no personal timetable should become a shared fixture.

### 2026-11-22 — incomplete-publication / daytime-observation / rotation-source
Model: OpenAI Codex. A week can end with a dated evening registration but no daytime rows and then an empty teaching date. Treating that evening as a contradictory daytime roster hid later occurrences of the same Day. Separate the coverage of the two parts of the day and disclose when a partial date displays the verified daytime timetable. Retain explicit vacant slots even when an evening lesson accompanies them. Interfaces: `SchoolTimetable.Day.usesDaytimeRotation` is display-only; no archive, API, authentication or notification contract change. Regression: `SchoolTimetableRotationCoverageTests` and the native `--annual` journey with a truncated publication.

Verification: 262 Swift tests (including the rebuilt loopback Rust integration), 32 portal bridge tests, the bilingual catalog check and the native iPad offline journey passed. Build 0.3 (7) was installed in place and launched on a physical iPad. A read-only post-install comparison covered the complete published year, checking both page projections against repeated dated classes, lunch intervals, vacancies and existing late entries. No student records are included in the repository or test fixtures.

### 2026-11-22 — missing-future-days / late-variation / offline-restore
Model: OpenAI Codex. Comparing the entire day as one unit let an evening variation suppress otherwise corroborated instruction across subsequent weeks. Compare instructional and late periods separately when justified by the campus profile, and reconstruct the archived index on restore. Interfaces: existing date/reminder projections, `rebuildRotations(calendar:)` and an optional publication for `SchoolTimetableStore`; no changes to school endpoints, account boundaries, or archive schema. Regressions: `SchoolTimetableRotationCoverageTests`, and the iPad `--annual` offline-next-term scenario.

Verification: 259 Swift tests and 32 portal bridge tests passed. The native iPad simulator showed the expected next-term class in both Today and Planner after a cold launch without network access. Release 0.3 (6) was installed in place on a physical iPad and its build number read back; these fixture tests do not measure the coverage of a particular student's saved timetable.

### 2026-11-22 — study-week / closure-return
Model: OpenAI Codex. SchoolStudyWeek derives enrollment, ordinary weekdays and each week’s observed evening interval from the current owner’s dated records, independently of the six teaching-Day lineups. One constant time needs multiple weeks; a two- or three-week sequence needs each phase corroborated twice within one uninterrupted segment. Conflicts or an interrupted alternating phase are not guessed. A dated exception wins. An eligible Sunday or the last published holiday before teaching uses the incoming school week; a Friday departure, conference and unselected student do not acquire a projected TSSA. Derived rows are display only and cannot add an alert or turn a return into a teaching day. Tested with held-out weeks, unrelated synthetic enrollments, closure, cancellation, offline restoration and different time patterns. Interface: Day.studyTimePending; see SchoolStudyWeekTests.

### 2026-11-22 — timetable-display / supplemental-courses
Model: OpenAI Codex. SchoolBellAlignment accepts a complete corroborated four-block clock pattern in addition to split lessons. CampusBells.teachingGroups owns the internal breaks and lunch; arbitrary long appointments are not split. New snapshots use bell revision 2; older snapshots align at projection without rewriting the protected file. SchoolStudyWeek exposes the same roster-token classification to timetable display. No additional school read.
